## Deeper fixes

A second pass tested whether each problem is fixed at the right layer. It used real chrome-headless-shell 127 and 150 output (probe scripts `ax-probe*.mjs`, `cookie-probe.mjs`, `passage-probe*.mjs`, `stage-probe.mjs` and `reason-probe.mjs` in the review scratchpad).

- **Image-held prices (#8).** Fixing the role check is not enough: Puppeteer's default pruning also removes the card containers the heading matching relies on. Instead, write price-like `aria-label`/`alt` text into light-DOM text in the injected browser script, before serialization. Then drop the `accessibilityTree` format and the heading matching.
- **Cookie banners (#2).** The test fixtures are CookieYes and CookieScript banners, and `CONSENT_DISMISS_SCRIPT` has no selectors for either. Add their reject buttons and banner roots to the browser script, and remove consent roots from the DOM instead of hiding them. HTML, Markdown and screenshot then agree, and the text heuristics can go. Also, `source-cleanup.ts` is fingerprinted, so every regex tweak changes the rubric id. That drops every existing capture from current comparisons until pages are rescanned.
- **Evidence windows (#3, #5).** Use content-anchored chunks: split at headings and blank lines, pack whole paragraphs up to 1200 chars, and repeat the table header on continuation chunks. For selection and validation, drop the per-candidate ±250-char snippets and send the full source (at most 72 KB) once, as the page-wide evaluation already does.
- **Two verification paths (#10).** Keep one pipeline in which only the evidence location differs, feeding one shared validation step with the code-level guards. The direct path also omits the "Do not calculate or infer amounts" instruction and the 24,000-char gate.
- **Capacity errors (#7, #9, #11).** Raise one typed budget error (`NonRetryableError` carrying a code) from a single request budget in `jevDecisions`, and map it to a public reason by code, not by regex. The 253-passage and 254-quantity checks can never trigger under the 72 KB cap.
- **Per-offer policies (#6).** Ask the full policy catalog per offer in the existing batched run: 24 offers × 7 policies is about 3 requests. If the gate stays, count the gated-out keys in `coverage.policyUncertain`.

## New in the second pass

- **The directory switches populations based on which filters are present.** In `packages/api/src/routers/directory.ts:204`, a `signal` or `choiceKey` filter selects the 14-day benchmark population; anything else selects the full catalog. Removing the "States" chip therefore silently widens the list to stale and old-rubric pages. A bookmarked bar link later shows only captures at most 14 days old, with no indication. Make it an explicit `population: "benchmark" | "catalog"` field in the filter, URL and API input, set by chart bars. Note the `DirectoryFilter` doc comment says no such translation exists.
- **Dead branch in the pricing-facts panel.** `PricingFactsPanel` now filters out `not_disclosed` policies but keeps its "No disclosure found in this capture" branch.

## Smaller items in the same work

- `apps/web/src/routes/index.tsx`: the new tag reads "1 listed prices". It also renders outside the tag row, so it sits on its own line.
- `packages/api/src/routers/directory.ts`: `directory.list` now ships each row's full `numericPrices` JSON, up to ~1.7 MB raw per 50 rows, only to show a count. Return the count instead.
- `verifyFactEvidence` duplicates the validation half of `verifySourceChanges`, and the two prompts have already drifted apart.
- There are 7 hand-rolled batch loops, and an `answers.length !== checks.length` guard that can never be true.
- `sourceBlocks` and `evidenceCandidates` are two 1200-char splitters with different cut rules. `readExamples` is now used only by tests.
- Not regressions, but worth knowing:
  - `verifyFactEvidence` uses fixed batches of 8 with no halving, so dense CJK or Cyrillic pages exceed the 30 KB budget.
  - `collectBenchmarkCorpus` throws above 20,000 rows, before `runWeeklyComparisons` runs.
